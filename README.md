# 四店服装零售 POS

FastAPI + Vue + PostgreSQL 的局域网零售系统。四家门店分别维护库存，总部管理员可查看汇总并进行跨店调拨。

## 已实现

- SPU 款式与颜色/尺码 SKU
- 每店独立库存、低库存筛选和 Code128 条码
- 原子扣库存、防超卖、多商品收银和销售请求防重
- 单 SKU 与多 SKU 调拨、在途库存、部分收货和拒收
- 盘点单及盘点期间库存冲突检测
- 部分/整单退款、独立退款单和退款请求防重
- 账号权限、安全 Cookie 会话、CSRF 防护和操作审计
- PostgreSQL 连接池及一键启动

## 一键启动

双击 `start.bat`。第一次启动会创建虚拟环境、安装固定版本依赖，并询问 PostgreSQL 和初始管理员配置。

- 本机：http://127.0.0.1:8000
- 局域网：`http://服务器内网IP:8000`
- API 文档：http://127.0.0.1:8000/docs

正式服务器应配置 HTTPS，并在 `.env` 中设置 `COOKIE_SECURE=true`。不同地点的门店应通过 VPN 访问，不要把 8000 端口直接开放到公网。

## 库存原则

`Inventory(sku_id, store)` 是唯一的业务库存来源。旧的 `Sku.quantity` 只为兼容早期数据保留，新库存变化必须经过入库、出库、销售、退款、调拨或盘点接口，以保证流水完整。

批量创建 SKU 时填写的初始库存进入 1 号店。更推荐初始库存填 0，创建后通过正式入库功能录入实际到货门店。

批量调拨每次收货都使用独立的 `client_request_id`。同一笔收货重试返回原结果，不再增加库存或重复记流水；下一批实际到货使用新编号。浏览器会在当前标签页保存待确认的收货，刷新页面或关闭收货弹窗后可以继续确认。不要在结果未确认时清除浏览器存储或关闭标签页。

升级收货防重功能后，需要重启后台并刷新所有收货终端的页面。启动时自动创建 `stocktransferreceipt` 表，保留现有调拨和库存数据。旧客户端缺少请求编号时会被拒绝，不会写入库存。

收银时必须等全部条码查询完成后才能结算。结算等待期间，扫码、改数量、删商品、清空、切店和登出均暂停；购物车有商品时，需先结算或清空再切店。清空、退出登录或更换门店后，旧条码查询结果不会重新加入购物车，也不会影响新账号的订单。

盘点现在整单一次提交：实盘数、库存差异、流水及完成状态共同成功或回滚。录入、完成和取消使用同一张单据锁及版本检查，过期页面不会覆盖其他管理员的修改。冲突后保留页面上的实盘数，重新加载前会要求确认；若盘点期间发生销售或其他库存变化，仍需取消旧单并重新盘点。

升级盘点功能时需要重启后台，并刷新所有终端页面。启动会为现有 `inventorycount` 表补上 `version` 字段，不删除历史数据。旧版客户端缺少版本或整单明细时会被拒绝。盘点完成接口改为同时提交 `expected_version` 和完整 `items`（`item_id`、`actual_qty`）；单行录入及取消接口同样需要 `expected_version`。

## 功能检查

在 `backend` 目录运行 `python -m unittest discover -p "test_*.py" -v`，使用独立测试数据库检查业务行为。在项目根目录运行 `node --test backend/test_transfer_receipts_frontend.cjs backend/test_checkout_frontend.cjs backend/test_inventory_counts_frontend.cjs`，模拟网络错误、刷新恢复、延迟扫码、切换账号及盘点冲突。这些检查不包含并发压力测试；SQLite 回归和 PostgreSQL 锁语句编译检查不能替代真实 PostgreSQL 多连接验证。

## B21 服装吊牌贴纸

库存中的“条码”按钮现在按参考吊牌生成 40×60 mm 合格证贴纸，顺序为品名、款号、颜色、规格、成份、执行标准、安全技术类别、原 SKU 的 Code128 条码和价格，不含裤型。规格加大显示，价格放在底部；吊牌价未填写时使用 SKU 售价并标注“售价”，不虚构建议零售价。

管理员可在标签窗口填写并保存每款商品的成份、执行标准、适用人群及安全类别，四店共用。核对原吊牌、供货资料或检测报告后勾选确认，才开放正式下载和打印。资料不全时只生成“合格证预览”，不会把现有商品自动标为合格；修改品名或品类后需重新核对。资料保存带版本校验和审计，过期编辑不会覆盖其他管理员的更改。

商品录入提供羊绒衫、牛仔裤、风衣、连衣裙、羽绒服、羊绒大衣、休闲裤、衬衫、半袖、棉服、套装、针织衫这 12 个品类。品类和标准目录由同一后端接口提供，历史自定义品类保留；新提交的“莲衣裙”统一为“连衣裙”，不批量重写已有商品。

内置 19 项经官方资料核对的执行标准，标签窗口按品类分组显示参考选项，注明针织/机织、材料和款式区别、官方来源及已发布新版的实施日期，仍支持手动填写其他标准号。切换“标准参考品类”只调整参考排序，不修改真实商品品类、已有执行标准或安全类别。套装各件信息不同的须分别标识，半袖区分 T 恤和短袖衬衫，不按款名自动认定合格性。

安全类别增加 A/B/C 适用条件、常见服装例子，以及儿童、婴幼儿的额外说明。直接接触皮肤的非婴幼儿产品至少 B 类，非直接接触皮肤至少 C 类，婴幼儿须 A 类；贴身与外穿羊绒衫、针织衫按实际接触方式核对。安全类别不等于质量等级，系统拦截明显低于最低要求的选择，但不能替代检测。参见 [标准来源与适用说明](docs/label-standards.md)。本贴纸不能替代原有厂商信息、洗护、羽绒种类、充绒量等完整标识。

- 精臣 B21：203 dpi，输出为 320×480 像素黑白 PNG；条码保持整数像素和左右静区。
- 精臣免驱软件：下载标签 PNG，在精臣软件中建立 40×60 mm 标签，插入图片并按整张标签放置，然后选择 B21 打印。图片不得拉伸、裁掉条码两侧空白或叠加软件自己的条码。
- 系统打印：需要 B21 出现在 Windows 的系统打印机中；预览支持 1 到 100 张，纸张选择 40×60 mm、比例 100%、页边距 0，并关闭页眉页脚。PNG 下载保存一张原图，份数在精臣软件中设置。

免驱软件连接设备并不等于安装 Windows 打印驱动，浏览器不能枚举专用软件内部的打印机。精臣官方提供 Web / C# / C++ SDK，但开发包与调用文档需向官方申请；本项目当前没有官方 SDK，不声明已实现 B21 USB 直连。见 [精臣开发者支持](https://www.niimbot.com/hk/developer_work_order) 和 [精臣软件下载](https://www.niimbot.com/us/downloadCenter?showDetail=true)。

Windows 默认使用微软雅黑字体；Linux 服务器需安装 Noto Sans CJK，或通过 `LABEL_FONT_PATH` 指定已有中文字体的绝对路径。没有中文字体时返回明确错误，避免打印空白字。条码或文字太长、无法在 40 mm 宽度内清晰完整排版时会拒绝生成。

在 `backend` 中运行 `python -m unittest test_labels test_product_labels -v` 检查标签内容、条码像素、资料确认和升级兼容。可用 `python preview_labels.py --output ../label-preview/qualified-tag-40x60mm.png` 生成明确标注“样板”的参考图，不访问门店数据库，不更改真实 SKU。实物连接、走纸和扫码效果仍需在 B21 上试打一张确认。
