# 四店服装零售 POS

FastAPI + Vue + PostgreSQL 的局域网零售系统。四家门店分别维护库存，总部管理员可查看汇总并进行跨店调拨。

## 已实现

- SPU 款式与颜色/尺码 SKU
- 新款一体录入、逐规格库存预览、同款选择性批量改价和单品库存纠错
- 每店独立库存、低库存筛选和 Code128 条码
- 原子扣库存、防超卖、多商品收银和销售请求防重
- 单 SKU 与多 SKU 调拨、在途库存、部分收货和拒收
- 盘点单及盘点期间库存冲突检测
- 部分/整单退款、独立退款单和退款请求防重
- 日流水、月度流水、四店汇总和支付方式统计
- 现金/微信/支付宝/刷卡支付记录、订单备注和小票快照
- 账号权限、安全 Cookie 会话、CSRF 防护和操作审计
- PostgreSQL 连接池及一键启动

## 一键启动

双击 `start.bat`。第一次启动会创建虚拟环境、安装固定版本依赖，并询问 PostgreSQL 和初始管理员配置。

- 本机：http://127.0.0.1:8000
- 局域网：`http://服务器内网IP:8000`
- API 文档：http://127.0.0.1:8000/docs

正式服务器应配置 HTTPS，并在 `.env` 中设置 `COOKIE_SECURE=true`。不同地点的门店应通过 VPN 访问，不要把 8000 端口直接开放到公网。

## 库存原则

`Inventory(sku_id, store)` 是唯一的业务库存来源。旧的 `Sku.quantity` 只为兼容早期数据保留，新库存变化必须经过入库、出库、销售、退款、调拨、盘点或库存纠错接口，以保证流水完整。

### SKU 归档

- 在售、停用、归档分开处理。“含停用”不会显示归档 SKU；管理员/店长可从“归档商品”搜索、分页查看并恢复。
- 归档前检查所有门店库存必须为零、没有该 SKU 的在途/待收货调拨、没有包含它的未完成盘点单。执行时再次核对并锁定 SKU 与库存，拒绝过期版本。
- 归档保留原条码、规格、销售、退货、库存、调拨和盘点历史，不释放条码或重复创建同规格。归档 SKU 禁止直接启用、改价、纠错、入出库、销售或新调拨，新盘点单也不包含它。
- 恢复后保持停用，不自动上架；在库存查询勾选“含停用”后可核实并启用。历史订单退货仍可办理，会在退款事务中自动恢复为停用并记录审计，再入库；失败时一起回滚。
- 永久删除仅限无库存且没有上述任何业务记录的误建 SKU。确认框展示阻止原因，符合归档条件时可改为归档，整款删除也不能绕过历史保护。
- 归档、恢复和新版删除提交保存请求回执，网络中断时用“重试确认”确认原操作，不能修改请求内容后重试。旧库启动时自动增加可空的归档时间字段，原有 SKU 状态不变。

新款录入可选择初始入库门店，每个颜色/尺码分别填写数量，其余门店初始为 0。旧版“为已有款式追加规格”入口的初始库存仍进入 1 号店；给已有 SKU 补货应使用入库，不能重复生成规格。

批量调拨每次收货都使用独立的 `client_request_id`。同一笔收货重试返回原结果，不再增加库存或重复记流水；下一批实际到货使用新编号。浏览器会在当前标签页保存待确认的收货，刷新页面或关闭收货弹窗后可以继续确认。不要在结果未确认时清除浏览器存储或关闭标签页。

升级收货防重功能后，需要重启后台并刷新所有收货终端的页面。启动时自动创建 `stocktransferreceipt` 表，保留现有调拨和库存数据。旧客户端缺少请求编号时会被拒绝，不会写入库存。

收银时必须等全部条码查询完成后才能结算。结算等待期间，扫码、改数量、删商品、清空、切店和登出均暂停；购物车有商品时，需先结算或清空再切店。清空、退出登录或更换门店后，旧条码查询结果不会重新加入购物车，也不会影响新账号的订单。

盘点现在整单一次提交：实盘数、库存差异、流水及完成状态共同成功或回滚。录入、完成和取消使用同一张单据锁及版本检查，过期页面不会覆盖其他管理员的修改。冲突后保留页面上的实盘数，重新加载前会要求确认；若盘点期间发生销售或其他库存变化，仍需取消旧单并重新盘点。

升级盘点功能时需要重启后台，并刷新所有终端页面。启动会为现有 `inventorycount` 表补上 `version` 字段，不删除历史数据。旧版客户端缺少版本或整单明细时会被拒绝。盘点完成接口改为同时提交 `expected_version` 和完整 `items`（`item_id`、`actual_qty`）；单行录入及取消接口同样需要 `expected_version`。

## 功能检查

先在 `backend` 目录安装开发测试依赖：`python -m pip install -r requirements-dev.txt`，再运行 `python -m unittest discover -p "test_*.py" -v`，使用独立测试数据库检查业务行为。在项目根目录运行 `node --test backend/test_*_frontend.cjs`，模拟网络错误、刷新恢复、延迟扫码、切换账号及盘点冲突。这些检查不包含并发压力测试；SQLite 回归和 PostgreSQL 锁语句编译检查不能替代真实 PostgreSQL 多连接验证。

## 简化录入与纠错

- **同款批量改价**：商品录入的“已有款式”中点击“批量改价”，勾选具体规格，再单独选择修改成本、售价或两者。确认窗口显示原值与新值，默认不选任何规格；价格四店共用，不改库存、条码、吊牌价或历史订单。任一规格版本过期时整批回滚，重新读取后核对再提交。
- **新款录入**：填写款式、可选吊牌资料、颜色、尺码和默认金额，生成规格预览后逐行调整售价、成本、库存和安全库存；核对初始入库门店后确认。款式、全部 SKU、四店库存和初始入库流水共同提交或回滚。款号已经存在会拒绝，不会覆盖原商品。未核实的成份、标准、安全类别保持待核实，不自动猜测或开放打印。
- **单品库存纠错**：库存查询点击“单品纠错”扫描条码，或点击某一行的“纠错”；读取具体门店最新库存后填写实际数量和必填原因，确认前显示差额。停用 SKU 也可纠错。数量与最后变动时间双重校验，期间发生销售、调拨、入库或盘点则拒绝旧快照，须重读并重新核实；留调整流水和操作审计，不改其他门店。

三项操作均限管理员/店长，后台保存请求编号及原结果，网络重试不会重复录入或调整。响应不确定时保留同一请求和内容，禁止改内容、切店、退出或关闭弹窗，点击“重试确认”核实结果。浏览器离页会提醒，但待确认状态仍只保存在当前页面内存中，不要强制刷新或关闭。升级后重启后台并刷新所有终端页面，启动会自动创建 `managementoperation` 表，保留已有业务数据。

## 支付与日月流水

库存查询中，管理员/店长可点击 SKU 的“改价”修改成本和售价；四店共用同一 SKU 价格，不修改原条码、库存、吊牌价或历史订单成交金额。编辑先读取最新数据，保存带版本校验；发生冲突须重新加载核对，改价留操作审计。结算待确认时不能打开改价。启动时自动为既有 SKU 添加版本字段，不重建 SKU。库存录错通过对应门店盘点或单品纠错调整，不能靠修改批量生成表单覆盖已有 SKU。已打印的旧售价贴纸不会自动变更，采用“当前售价”打印的标签需按新售价重新打印。

在收银购物车选择现金、微信、支付宝或刷卡，并填写最多 500 字的订单备注。支付方式和备注随订单保存，明细及重打小票显示原记录；这里只记录线下实际收款方式，不连接微信/支付宝/银行卡支付网关，不会自动收款或验证到账。

账单区提供订单明细、日流水、月度流水。现有管理员和店长同属 `manager` 管理角色，可看四店汇总或指定单店；`staff` 店员只能查询所属门店，后端对跨店请求返回 403。切换账号立即清除旧流水和订单明细，迟到的网络响应不能恢复上一账号的数据。

默认按 `BUSINESS_TIMEZONE=Asia/Shanghai` 的自然日和自然月统计，金额以分累计。销售额按原订单生成时间和销售门店计入；退款额按独立退款单的实际生成时间和退款门店计入，支付方式按原销售订单归类。净流水 = 当期销售额 - 当期退款额，可能为负数；跨日、跨月、跨店退款不会改写原销售日流水。仅修改订单累计退款字段、没有独立退款单的早期数据无法确定退款发生日，不能据此伪造退款流水。

月度流水列出每个自然日（含零流水日），可进入单日或查看该期间销售订单。汇总在数据库中查询全部匹配记录，不受订单列表最新 200 单的显示限制。启动时自动增加可空的 `salesorder.payment_method` 和门店/时间索引；既有订单的支付方式保持“未记录”，不冒认为现金，不改库存、订单金额、账号或旧备注。

结算等待或响应不确定时，当前页面固定同一请求号、商品数量、支付方式和备注，暂停修改、扫码、清空、切店及登出，重试确认后才能开始下一单。明确的校验失败允许更正再提交。结果待确认时不要刷新或关闭收银页面；本次收银待确认状态只保留在当前页面内存中。

## B21 服装吊牌贴纸

库存中的“条码”按钮现在按参考吊牌生成 40×60 mm 合格证贴纸，顺序为品名、款号、颜色、规格、成份、执行标准、安全技术类别、原 SKU 的 Code128 条码和价格，不含裤型。规格加大显示，价格放在底部；吊牌价未填写时使用 SKU 售价并标注“售价”，不虚构建议零售价。

管理员可在标签窗口填写并保存每款商品的成份、执行标准、适用人群及安全类别，四店共用。核对原吊牌、供货资料或检测报告后勾选确认，才开放正式下载和打印。资料不全时只生成“合格证预览”，不会把现有商品自动标为合格；修改品名或品类后需重新核对。资料保存带版本校验和审计，过期编辑不会覆盖其他管理员的更改。

商品录入提供羊绒衫、牛仔裤、风衣、连衣裙、羽绒服、羊绒大衣、休闲裤、衬衫、半袖、棉服、套装、针织衫、T恤衫、小衫、裤子、上衣、半裙、马甲这 18 个品类。商品录入和条码/吊牌编辑共用同一后端品类与标准目录，历史自定义品类保留；新提交的“莲衣裙”统一为“连衣裙”，不批量重写已有商品。

内置 19 项经官方资料核对的执行标准，标签窗口按品类分组显示参考选项，注明针织/机织、材料和款式区别、官方来源及已发布新版的实施日期，仍支持手动填写其他标准号。切换“标准参考品类”只调整参考排序，不修改真实商品品类、已有执行标准或安全类别。套装各件信息不同的须分别标识，半袖区分 T 恤和短袖衬衫，不按款名自动认定合格性。

安全类别增加 A/B/C 适用条件、常见服装例子，以及儿童、婴幼儿的额外说明。直接接触皮肤的非婴幼儿产品至少 B 类，非直接接触皮肤至少 C 类，婴幼儿须 A 类；贴身与外穿羊绒衫、针织衫按实际接触方式核对。安全类别不等于质量等级，系统拦截明显低于最低要求的选择，但不能替代检测。参见 [标准来源与适用说明](docs/label-standards.md)。本贴纸不能替代原有厂商信息、洗护、羽绒种类、充绒量等完整标识。

- 精臣 B21：203 dpi，输出为 320×480 像素黑白 PNG；条码保持整数像素和左右静区。
- 精臣免驱软件：下载标签 PNG，在精臣软件中建立 40×60 mm 标签，插入图片并按整张标签放置，然后选择 B21 打印。图片不得拉伸、裁掉条码两侧空白或叠加软件自己的条码。
- 系统打印：需要 B21 出现在 Windows 的系统打印机中；预览支持 1 到 100 张，纸张选择 40×60 mm、比例 100%、页边距 0，并关闭页眉页脚。PNG 下载保存一张原图，份数在精臣软件中设置。

免驱软件连接设备并不等于安装 Windows 打印驱动，浏览器不能枚举专用软件内部的打印机。精臣官方提供 Web / C# / C++ SDK，但开发包与调用文档需向官方申请；本项目当前没有官方 SDK，不声明已实现 B21 USB 直连。见 [精臣开发者支持](https://www.niimbot.com/hk/developer_work_order) 和 [精臣软件下载](https://www.niimbot.com/us/downloadCenter?showDetail=true)。

Windows 默认使用微软雅黑字体；Linux 服务器需安装 Noto Sans CJK，或通过 `LABEL_FONT_PATH` 指定已有中文字体的绝对路径。没有中文字体时返回明确错误，避免打印空白字。条码或文字太长、无法在 40 mm 宽度内清晰完整排版时会拒绝生成。

在 `backend` 中运行 `python -m unittest test_labels test_product_labels -v` 检查标签内容、条码像素、资料确认和升级兼容。可用 `python preview_labels.py --output ../label-preview/qualified-tag-40x60mm.png` 生成明确标注“样板”的参考图，不访问门店数据库，不更改真实 SKU。实物连接、走纸和扫码效果仍需在 B21 上试打一张确认。
