四店并发与备份说明
==================

当前设计：
1. 四个店铺共用同一个 PostgreSQL 数据库。
2. 库存按门店拆分，Inventory 表中每个 SKU 在每家店各有一条库存记录。
3. 收银只扣当前门店库存，库存不足时不会扣成负数。
4. 库存页可查看单店库存；管理员可查看全部门店汇总库存。
5. 多件商品结算时按 SKU 编号固定顺序扣库存，减少两个收银台互相等待造成死锁的概率。
6. 每次结账前端都会生成 client_request_id，避免网络卡顿或双击按钮造成重复订单。
7. 退款逐行做条件更新，并回补到原订单门店库存，最后按数据库最终明细重算订单退款金额和状态。
8. PostgreSQL 连接池已给 4 店多终端留余量。

建议部署：
1. 选一台稳定电脑或小服务器作为中心服务器。
2. PostgreSQL 和本系统都跑在中心服务器上。
3. 四家店用浏览器访问 http://中心服务器IP:8000。
4. 中心服务器尽量接 UPS，避免断电损坏数据库。
5. 收银电脑不要随便安装浏览器插件，不要用于浏览无关网站。

备份：
1. 双击 backup.bat 可手动备份 PostgreSQL。
2. 备份文件会生成在 backups 目录。
3. 建议用 Windows 任务计划每天闭店后自动运行 backup.bat。
4. backups 目录建议同步到网盘或复制到 U 盘/移动硬盘。

后续还值得增强：
1. 增加 SKU 下架/停用字段，避免历史商品被删除。
2. 增加改价日志，记录谁在什么时候改了价格。
3. 手动出库、盘点调整建议只允许店长操作。
4. 使用 Alembic 做数据库版本迁移。
5. 增加正式店间调拨功能：from_store + to_store + sku_id + quantity。
